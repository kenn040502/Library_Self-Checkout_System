# Sprint 4 Report Writing Order

建议写作顺序：

1. Sprint Plan
   - 先写 Sprint 4 原本打算做什么。
   - 重点：final sprint、bug fixing、wrap up、handover preparation、final testing。
   - 这个 section 会成为 Sprint Review 的对照标准。

2. Sprint Review
   - 写实际完成了什么，以及跟 Sprint Plan 对比怎样。
   - 可以从 GitHub commits / repo changes 抽资料。
   - 需要包括：
     - Progress made on sprint backlog
     - Client feedback for this sprint
     - Critical analysis of progress, challenges, and deliverable status

3. Contribution Details
   - 等 Sprint Review 的成果整理出来后，再分配到每个人贡献会比较容易。
   - 每个人都要有 evidence，例如 GitHub commits、screenshots、research summary、test result。
   - Kelvin 的部分可以之后让 Codex 根据 GitHub commit 记录帮忙写。

4. Contribution Summary Table
   - 这个是 summary table，最好等 Contribution Details 差不多确定后再微调。
   - 现在文档里已经有内容，可以最后再润色。

5. Project Review
   - 写整个项目从开始到最终完成了什么。
   - 重点不是只看 Sprint 4，而是看整个 project 的 planned deliverables vs achieved deliverables。
   - 可以参考之前 sprint plan、final features、changes in scope。

6. Retrospect
   - 写 Sprint 4 的团队流程反思。
   - 你可以自己写。
   - 重点：team process、challenges、bottlenecks、how the team dealt with them。

7. Project Retrospect
   - 最后写整个项目的大反思。
   - 包括：
     - Project management approach
     - Ethical standards
     - Requirement engineering
     - Plan and design
     - Quality
     - Stakeholder management
     - Team process
   - 这一节比 Sprint Retrospect 更总结性，所以放后面写比较顺。

8. Final Delivery and Feedback
   - 这部分最好等 client handover / final meeting 后再写。
   - 如果还没发生，先留 placeholder，不要硬编。
   - 最后需要写：
     - Delivered items
     - Handover plan
     - What was achieved
     - What remains to be done
     - How to use the deliverables
     - Client feedback
     - Future improvements

## Quick Version

最推荐实际写作顺序：

```text
Sprint Plan
-> Sprint Review
-> Contribution Details
-> Contribution Summary
-> Project Review
-> Retrospect
-> Project Retrospect
-> Final Delivery and Feedback
```

注意：Final Delivery and Feedback 可以先跳过，等 handover / client feedback 后再补。

## Sprint Plan Rubric Focus

Sprint Plan is worth 15 marks.

To score in the Good range, the Sprint Plan should be:

- Practical
- Detailed
- Complete
- Logically connected to previous sprints

When writing Sprint Plan, make sure it explains:

- Why Sprint 4 is different from earlier sprints because it is the final sprint.
- How Sprint 4 continues from previous sprint outcomes.
- What the team planned to prioritise.
- Who was responsible for coordination and major work areas.
- How the team planned to move from implementation to stabilisation, testing, reporting, and handover.

Suggested Sprint Plan structure:

```text
Sprint Context
Sprint Goal
Connection to Previous Sprints
Team Roles
Planned Tasks
Sprint Backlog / Priorities
Expected Outcome
```

Important: Sprint Plan should not only say "we planned to finish the project". It should explain what "finish" means in practical terms, such as bug fixing, testing, screenshots, evidence collection, final report writing, handover preparation, and client feedback collection.
